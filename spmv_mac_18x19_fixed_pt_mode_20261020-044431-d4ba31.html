  • Same behavior. The rewritten design must produce the same outputs as the original on every cycle, with every register of the original starting at 0. Do not change what the design computes. Logic added only to reproduce it (recomputing a value, deriving the block's reset, correcting a block's result) is allowed.

  • Terms. Keep every term of the original arithmetic. A term with no matching block port is computed outside the block. A port the design ties to a constant may be tied the same way on the block.

  • Assumptions. If the rewrite is correct only under an assumption about the design's inputs or use (a bound on a value, when a signal is asserted), state it on a line starting ASSUMES: and cite the lines of the design that support it. The rewrite is verified under that assumption.
Cost (guidance: go against it only with a reason in the plan)
  • The clock period is the delay of the slowest stage (the logic between one register and the next). A rewrite that does not touch the slowest stage should not be expected to make the design faster, and should not make another stage slower than it.
  • Blocks in series are separate stages.
  • Moving or adding registers changes stage lengths and when values arrive.
  • Area falls when soft adders and flip-flops move into blocks.
  • A DSP tile holds two blocks of this mode. Blocks in one tile share one clock and one reset, so blocks on different reset signals cannot share a tile. Synthesis may already have placed the design's multiplies on tiles, so a block that only replaces one saves little: count tiles against the baseline.

Candidate 1 — Channel.$mul$spmv.v:3317$75, 32 instances (spmv.v:3312-3323). Left: the block's 2-cycle latency cannot be hidden, and its unconditional accumulate cannot reproduce the register's hold.

  • Baseline register stages for this region: operands → result is exactly 1 stage. vec_val and mat_val are valid during the cycle before edge k; at edge k the soft register mult captures vec_val * mat_val (spmv.v:3317), gated by vec_val_rd_en_reg && mat_val_rd_en_reg. With the block the same region would need 2 stages (operands sampled at edge k, out updated at edge k+1), which is one stage too many.
  • The one-cycle shortfall cannot be recovered by feeding the block earlier. Both operands are the registered read-port outputs of the FIFO memories: generic_fifo_sc_a (spmv.v:3586) drives dout from dpram.out_a, which is a clocked register (out_a <= ram[address_a], spmv.v:3714). There is no combinational path to the data one cycle ahead, and the read pointer rp (spmv.v:3648-3653) advances on re that is itself computed in the current cycle (spmv.v:3309-3310), so the next operand pair is not predictable a cycle early. Nothing in the operand source can be moved into the block's input register to pay for the extra stage.
  • Absorbing the extra cycle downstream is also not legal. mult is consumed only by fifo_mult.din with we = mult_wr_en (spmv.v:3299-3300), and mult_wr_en is set at the same edge k that loads mult (spmv.v:3318), so the FIFO captures the product at edge k+1. Delaying we by one cycle to match a block output delays wp and the combinational empty flag (spmv.v:3662), which delays the Accumulator's mult_rd_en (spmv.v:3400) and therefore when entries appear in fifo_data_out. In spmv the drain is a free-running round-robin on counter/counter_delay (spmv.v:160-202), so any shift in when a channel's result becomes available changes which cycle wr_en/wr_addr/wr_data reach write_mem (spmv.v:204-214) and hence dout on a given cycle. Keeping we at its original edge while writing the data a cycle late loses the race against a read at edge k+2 (the FIFO's out_a would latch stale RAM contents). Either way, "same outputs on every cycle" fails.
  • Independently, the block's semantics do not match the register's. mult holds its value when vec_val_rd_en_reg & mat_val_rd_en_reg is low; the block has no enable and adds a term on every non-clearing edge, so a single block accumulates the garbage products of idle cycles. Clearing with reset every other edge also clears the operand registers, so one block yields at most one isolated product every two cycles, and two interleaved blocks per channel restore throughput but not the missing cycle of latency. (Widths and signedness are not the obstacle: vec_val/mat_val are 8-bit unsigned, the 16-bit product fits the 37-bit unsigned out with no wrap.)
  • Best case had it been legal: 32 blocks sharing rst, two per tile, 16 tiles instead of 32, i.e. about 7% of logic-block area, with the critical path untouched at 7.06559 ns. That upside does not exist under a correct rewrite, so it does not change the decision.
