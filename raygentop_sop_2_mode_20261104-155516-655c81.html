The algebra (why this is T2 and why only 3 blocks are needed)

In the baseline (raygentop.v:2860-2886) one clock edge loads ul<=u, vl<=v, wl<=255-u-v, rul<=ru … bwl<=bw; the same edge loads the nine products i1r<=ul*rul … i3b<=wl*bwl from the previous values of those registers; the outputs are r = (i1r+i2r+i3r), g, b — each assigned to a 7-bit port, so only bits [6:0] of each three-product sum are visible outside the module. ul,vl,wl and rul…bwl and i1r…i3b are read by nothing but these multiplies and these three sums (checked every occurrence in 2762-2887; the ul/vl at 2752/2756 are a different module, addrgen).

Because wl is 8-bit arithmetic, wl = (255 - ul - vl) mod 256, and 128 divides 256, so mod 128:

r ≡ ul·rul + vl·rvl + (255−ul−vl)·rwl ≡ ul·(rul−rwl) + vl·(rvl−rwl) + 255·rwl ≡ ul·(rul−rwl) + vl·(rvl−rwl) − rwl (mod 128)

and likewise for g and b. Each colour therefore needs two products instead of three, and each product's operands may be reduced mod 128 (u[6:0], and the 7-bit wrapping differences ru-rw etc.), because only bits [6:0] of the sum are read. Six products, two per block ⇒ three blocks, and wl (and its subtractor) disappears entirely. This is exact for all inputs — no bound, no assumption, so there is no ASSUMES: line. The algebra (why this is T2 and why only 3 blocks are needed)

In the baseline (raygentop.v:2860-2886) one clock edge loads ul<=u, vl<=v, wl<=255-u-v, rul<=ru … bwl<=bw; the same edge loads the nine products i1r<=ul*rul … i3b<=wl*bwl from the previous values of those registers; the outputs are r = (i1r+i2r+i3r), g, b — each assigned to a 7-bit port, so only bits [6:0] of each three-product sum are visible outside the module. ul,vl,wl and rul…bwl and i1r…i3b are read by nothing but these multiplies and these three sums (checked every occurrence in 2762-2887; the ul/vl at 2752/2756 are a different module, addrgen).

Because wl is 8-bit arithmetic, wl = (255 - ul - vl) mod 256, and 128 divides 256, so mod 128:

r ≡ ul·rul + vl·rvl + (255−ul−vl)·rwl ≡ ul·(rul−rwl) + vl·(rvl−rwl) + 255·rwl ≡ ul·(rul−rwl) + vl·(rvl−rwl) − rwl (mod 128)

and likewise for g and b. Each colour therefore needs two products instead of three, and each product's operands may be reduced mod 128 (u[6:0], and the 7-bit wrapping differences ru-rw etc.), because only bits [6:0] of the sum are read. Because wl is 8-bit arithmetic, wl = (255 - ul - vl) mod 256, and 128 divides 256, so mod 128:

r ≡ ul·rul + vl·rvl + (255−ul−vl)·rwl ≡ ul·(rul−rwl) + vl·(rvl−rwl) + 255·rwl ≡ ul·(rul−rwl) + vl·(rvl−rwl) − rwl (mod 128)
