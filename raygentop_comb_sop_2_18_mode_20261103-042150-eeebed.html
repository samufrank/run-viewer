What the source says

bilinearintrp (raygentop.v:2762-2887) registers its operands, then registers nine products one stage later, then sums them combinationally into three 7-bit outputs:

  • line 2862-2864: wl <= 8'b11111111 - u - v ; ul <= u ; vl <= v ; — all in one always @(posedge clk), so wl = (255 - ul - vl) mod 256 with matching time indices.
  • lines 2874-2882: i1r <= ul*rul ; i2r <= vl*rvl ; i3r <= wl*rwl ; and the same for g and b.
  • lines 2884-2886: assign r = (i1r + i2r + i3r) ; with output[6:0] r — the 15-bit sum is truncated to 7 bits. Only r, g, b leave the module; i1r..i3b and wl have no other reader (checked every use in the file), so nothing inside is visible except the three 7-bit sums.

ru,rv,rw,gu,...,bw come from shadedata = tm3_sram_data_in (raygentop.v:2012, 676, 25) — a top-level input, combinational. So the stage that ends at the r*l/g*l/b*l registers starts at an I/O pad, which this run does not time.

The rewrite (all nine candidates converted, none left)

Because the outputs are 7 bits, everything is mod 128, and wl ≡ -1 - ul - vl (mod 128):

r = (ul*rul + vl*rvl + wl*rwl) mod 128
  = (ul*(rul-rwl) + vl*(rvl-rwl) - rwl) mod 128

Each difference may be taken as a plain 7-bit wrapping subtract: if d = (rul-rwl) mod 128 then ul*d = ul*(rul-rwl) + 128*k*ul ≡ ul*(rul-rwl) (mod 128), so the 7-bit wrap is exact for the bits that survive. Likewise 255*rwl ≡ -rwl (mod 128). This holds for all input values — no ASSUMES: line is needed, and it matches the testbench's full-width random stimulus.

So each colour's three products collapse to exactly the two products one comb_sop_2_18 provides, plus a 7-bit correction:

  1. In the input-register stage (pad-fed, untimed), replace rul <= ru ; rvl <= rv ; with rud <= ru - rw ; rvd <= rv - rw ; (7-bit), keep rwl <= rw, and add one more delay rwd <= rwl. Same for g and b.
  2. Instantiate one block per colour, combinational, driven by the ul/vl/r*d registers; the block's inputs are zero-extended to the port widths (ul,vl 8 bits → ax/bx[18], the 7-bit differences → ay/by[19]). ul*rud + vl*rvd ≤ 2*255*127 = 64770, so the block's 64-bit result never wraps.
  3. Register only the low 7 bits of each block result: sr <= res_r[6:0] (and sg, sb). These three 7-bit registers replace the nine product registers i1r..i3b.
  4. assign r = sr - rwd ; (7-bit wrap), and the same for g and b. This replaces the three-input adder trees at lines 2884-2886.
  5. Delete the wl register and wl <= 8'hFF - u - v — with all nine products converted, wl has no reader left. Delete i1r..i3b and the old rul/rvl/gul/... registers that the differences replace. The u/v selectuv mux (lines 2818-2858) and ul <= u ; vl <= v ; are unchanged.

Timing-index check: at edge T the block output is a function of registers written at edge T-1, and rwd written at edge T holds rw from edge T-1, so sr - rwd after edge T equals (i1r+i2r+i3r) mod 128 after edge T in the original. What the source says

bilinearintrp (raygentop.v:2762-2887) registers its operands, then registers nine products one stage later, then sums them combinationally into three 7-bit outputs:

  • line 2862-2864: wl <= 8'b11111111 - u - v ; ul <= u ; vl <= v ; — all in one always @(posedge clk), so wl = (255 - ul - vl) mod 256 with matching time indices.
  • lines 2874-2882: i1r <= ul*rul ; i2r <= vl*rvl ; i3r <= wl*rwl ; and the same for g and b.
  • lines 2884-2886: assign r = (i1r + i2r + i3r) ; with output[6:0] r — the 15-bit sum is truncated to 7 bits. Only r, g, b leave the module; i1r..i3b and wl have no other reader (checked every use in the file), so nothing inside is visible except the three 7-bit sums.

ru,rv,rw,gu,...,bw come from shadedata = tm3_sram_data_in (raygentop.v:2012, 676, 25) — a top-level input, combinational. So the stage that ends at the r*l/g*l/b*l registers starts at an I/O pad, which this run does not time.

The rewrite (all nine candidates converted, none left)

Because the outputs are 7 bits, everything is mod 128, and wl ≡ -1 - ul - vl (mod 128):

r = (ul*rul + vl*rvl + wl*rwl) mod 128
  = (ul*(rul-rwl) + vl*(rvl-rwl) - rwl) mod 128

Each difference may be taken as a plain 7-bit wrapping subtract: if d = (rul-rwl) mod 128 then ul*d = ul*(rul-rwl) + 128*k*ul ≡ ul*(rul-rwl) (mod 128), so the 7-bit wrap is exact for the bits that survive. Likewise 255*rwl ≡ -rwl (mod 128). This holds for all input values — no ASSUMES: line is needed, and it matches the testbench's full-width random stimulus.

So each colour's three products collapse to exactly the two products one comb_sop_2_18 provides, plus a 7-bit correction:

  1. In the input-register stage (pad-fed, untimed), replace rul <= ru ; rvl <= rv ; with rud <= ru - rw ; rvd <= rv - rw ; (7-bit), keep rwl <= rw, and add one more delay rwd <= rwl. Same for g and b.
  2. Instantiate one block per colour, combinational, driven by the ul/vl/r*d registers; the block's inputs are zero-extended to the port widths (ul,vl 8 bits → ax/bx[18], the 7-bit differences → ay/by[19]). ul*rud + vl*rvd ≤ 2*255*127 = 64770, so the block's 64-bit result never wraps.
  3. Register only the low 7 bits of each block result: sr <= res_r[6:0] (and sg, sb). These three 7-bit registers replace the nine product registers i1r..i3b.
  4. assign r = sr - rwd ; (7-bit wrap), and the same for g and b. This replaces the three-input adder trees at lines 2884-2886.
  5. Delete the wl register and wl <= 8'hFF - u - v — with all nine products converted, wl has no reader left. Delete i1r..i3b and the old rul/rvl/gul/... registers that the differences replace. The u/v selectuv mux (lines 2818-2858) and ul <= u ; vl <= v ; are unchanged.

Timing-index check: at edge T the block output is a function of registers written at edge T-1, and rwd written at edge T holds rw from edge T-1, so sr - rwd after edge T equals (i1r+i2r+i3r) mod 128 after edge T in the original. Latency is unchanged. The extra registers start unknown; the testbench's 8-cycle all-zero lead-in flushes them (they are at most 2 stages deep) before comparison begins.

Why all nine, and why none is left: the substitution only removes wl (and its adder and register) if every product that uses wl goes; converting one or two colours would keep wl alive and give a strictly smaller saving at the same tile count. There is no candidate with a reason to be left out.

3 blocks, each alone on a DSP tile. Baseline held the nine products in mult_9x9_fixed_pt on 3 tiles, so bilinear stays at 3 tiles and the design stays at 6 of 132 tiles — no DSP area change. 2 products per block is the floor here: a block emits only its own sum, so products of different colours can never share one, and after the substitution each colour needs exactly 2 products, i.e. exactly one block.

Expected cost

DSP area unchanged. Soft area falls: out go ~63 product flip-flops (the 15-bit i* registers reduce to the 7 bits the outputs read), ~36 adder cells of the three sum trees, and the 8-bit wl register plus its subtract; in come 21 sum flip-flops, 21 extra delay flip-flops, 21 subtract cells on the outputs, and six 7-bit subtracts that pack into the BLEs whose flip-flops already held rul/rvl 1:1. The rewrite (all nine candidates converted, none left)

Because the outputs are 7 bits, everything is mod 128, and wl ≡ -1 - ul - vl (mod 128):

r = (ul*rul + vl*rvl + wl*rwl) mod 128
  = (ul*(rul-rwl) + vl*(rvl-rwl) - rwl) mod 128

Each difference may be taken as a plain 7-bit wrapping subtract: if d = (rul-rwl) mod 128 then ul*d = ul*(rul-rwl) + 128*k*ul ≡ ul*(rul-rwl) (mod 128), so the 7-bit wrap is exact for the bits that survive. Likewise 255*rwl ≡ -rwl (mod 128). This holds for all input values — no ASSUMES: line is needed, and it matches the testbench's full-width random stimulus.

So each colour's three products collapse to exactly the two products one comb_sop_2_18 provides, plus a 7-bit correction:

  1. In the input-register stage (pad-fed, untimed), replace rul <= ru ; rvl <= rv ; with rud <= ru - rw ; rvd <= rv - rw ; (7-bit), keep rwl <= rw, and add one more delay rwd <= rwl. Same for g and b.

  4. assign r = sr - rwd ; (7-bit wrap), and the same for g and b. This replaces the three-input adder trees at lines 2884-2886.
