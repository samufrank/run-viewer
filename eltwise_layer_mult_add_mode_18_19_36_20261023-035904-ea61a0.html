A correct rewrite exists; it is left on cost, not on correctness. For the record, the correct form is:

  • One block per FPMult_16 instance, fed from the module ports a,b (not from pipe_0), so the block's own input registers load at the same edge as pipe_0 and mirror it: ax = {10'b0, 1'b1, a[6:0]}, ay = {11'b0, 1'b1, b[6:0]}, bx = 36'b0, chainin = 64'b0, scanin = 19'b0, mode_sigs = 12'b0, clk = clk, reset = rst; Mp taken from chainout[15:0], result/scanout unconnected. pipe_0 itself stays (its other bits feed Sa,Sb,Ea,Eb,InputExc at eltwise_layer.v:1993-2006), so nothing that another reader needs moves inside a block.
  • Register stages, before: operands a,b -> pipe_0 (1 stage) -> combinational multiply -> pipe_1. After: a,b -> block input registers (the same 1 stage, in parallel with pipe_0) -> chainout -> pipe_1. Same latency, same cycle-by-cycle values.
  • Reset: rst is synchronous active high and clears pipe_0 to 0 (eltwise_layer.v:1900-1906), so reset = rst keeps the block's operand registers in lock step with pipe_0. The one divergence is the cycle after a reset edge: the original computes Mp = {1'b1,7'b0}*{1'b1,7'b0} = 16'h4000 from the cleared pipe_0, while the cleared block gives chainout = 0. No correction logic is needed, because pipe_1[20:5] is read only as MpC by FPMult_ExecuteModule (eltwise_layer.v:1889, slices [44:38]/[37:21] do not touch it), and 16'h4000 and 0 are indistinguishable there: NormM = Mp[15] ? Each term is the median over the loop's seeds; the product is the product of the medians. Beside every product stand the ratios against the baseline, A/A0 (area), D/D0 (critical path), W/W0 (wirelength) and their product, so the normalization can be read off. After each measured rewrite, the planner is given every measurement so far and asked for a revision. A revision is built and checked like the first rewrite, and the lowest product is kept, a later rewrite having to beat it by more than 3.66%. The loop stops when the planner declines to revise, when a revision does not lower the best product by more than 3.66%, when a revision fails its checks, or when 9 revisions have been made.
