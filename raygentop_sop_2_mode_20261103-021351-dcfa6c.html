The regrouping (why all nine products are converted with only 3 blocks)

Because wl = (255-ul-vl) mod 256 and 256 ≡ 0 (mod 128), wl ≡ 255-ul-vl (mod 128), so mod 128:

r ≡ ul*rul + vl*rvl + wl*rwl
  ≡ ul*(rul-rwl) + vl*(rvl-rwl) + 255*rwl
  ≡ ul*A + vl*B - rwl        with A=(rul-rwl) mod 128, B=(rvl-rwl) mod 128

(255 ≡ -1 mod 128; and ul*A ≡ ul*(rul-rwl) mod 128 because A ≡ rul-rwl mod 128.) This is an identity for all input values — no bound on u+v is needed, so there is no ASSUMES: line. Each colour therefore collapses to exactly two variable products plus a 7-bit subtraction: one int_sop_2 per colour, 3 blocks total. The three wl*rwl-shaped products (2876, 2879, 2882) are not left in soft logic — they are absorbed into the two block products (ay/by become differences) plus the single -rwl2 subtract outside the block. No multiplier remains anywhere in the module.

Since ul*A ≤ 255*127 = 32385 and the block's sum ≤ 64770 < 2^37, the block's modulo-2^37 wrap never triggers; taking result[6:0] and subtracting the delayed rw in 7 bits reproduces the original mod-128 value exactly.

The regrouping (why all nine products are converted with only 3 blocks)

Because wl = (255-ul-vl) mod 256 and 256 ≡ 0 (mod 128), wl ≡ 255-ul-vl (mod 128), so mod 128:

r ≡ ul*rul + vl*rvl + wl*rwl
  ≡ ul*(rul-rwl) + vl*(rvl-rwl) + 255*rwl
  ≡ ul*A + vl*B - rwl        with A=(rul-rwl) mod 128, B=(rvl-rwl) mod 128

The regrouping (why all nine products are converted with only 3 blocks)

Because wl = (255-ul-vl) mod 256 and 256 ≡ 0 (mod 128), wl ≡ 255-ul-vl (mod 128), so mod 128:

r ≡ ul*rul + vl*rvl + wl*rwl
  ≡ ul*(rul-rwl) + vl*(rvl-rwl) + 255*rwl
  ≡ ul*A + vl*B - rwl        with A=(rul-rwl) mod 128, B=(rvl-rwl) mod 128

(255 ≡ -1 mod 128; and ul*A ≡ ul*(rul-rwl) mod 128 because A ≡ rul-rwl mod 128.) This is an identity for all input values — no bound on u+v is needed, so there is no ASSUMES: line. Each colour therefore collapses to exactly two variable products plus a 7-bit subtraction: one int_sop_2 per colour, 3 blocks total. The three wl*rwl-shaped products (2876, 2879, 2882) are not left in soft logic — they are absorbed into the two block products (ay/by become differences) plus the single -rwl2 subtract outside the block. No multiplier remains anywhere in the module.

Since ul*A ≤ 255*127 = 32385 and the block's sum ≤ 64770 < 2^37, the block's modulo-2^37 wrap never triggers; taking result[6:0] and subtracting the delayed rw in 7 bits reproduces the original mod-128 value exactly.

The regrouping (why all nine products are converted with only 3 blocks)

r ≡ ul*rul + vl*rvl + wl*rwl

The regrouping (why all nine products are converted with only 3 blocks)
