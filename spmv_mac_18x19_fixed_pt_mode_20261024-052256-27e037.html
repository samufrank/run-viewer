Candidate 1 — Channel.$mul$spmv.v:3317$75 (32 instances), left.

What it is (spmv.v:3285-3323): per channel, mult <= vec_val * mat_val in a clocked block with enable vec_val_rd_en_reg && mat_val_rd_en_reg and no rst branch; mult_wr_en is set at the same edge. mult has exactly one reader, fifo_mult.din (spmv.v:3299), and the FIFO's we is mult_wr_en (spmv.v:3300). Two independent blockers:

  1. Latency. vec_val/mat_val are registered dpram read ports inside generic_fifo_sc_a (spmv.v:3618-3631, dpram at spmv.v:3709-3716), so the popped operands first exist in the cycle in which vec_val_rd_en_reg/mat_val_rd_en_reg are high. Operands valid in cycle t ⇒ mult holds the product in cycle t+1, with mult_wr_en=1 in that same cycle, so the FIFO's dpram stores the product at edge t+2. The block is 2 cycles: operands applied in cycle t appear on out only in cycle t+2, i.e. one cycle after the FIFO must already have captured them. There is no earlier source for the operands (they are BRAM outputs; the address is known a cycle earlier but the data is not), and the consumer register is the FIFO's BRAM word, which cannot be moved. Delaying mult_wr_en by one cycle to match would shift every mult_full/mult_empty handshake, hence every Accumulator read, every data_out FIFO write and the free-running round-robin in spmv.v:160-202, so dout/done_reg would move in time — the strict same-cycle compare in tb_equiv_spmv.v:83-96 fails.
  2. Running sum vs. single product, no enable. The region's own row says "products reach no sum": each channel needs one standalone 16-bit product per enabled cycle, while the block has no enable and no load and its out is a running sum that can only be cleared, never reloaded. Zeroing a on non-enabled cycles suppresses a term but does not expose the last term. Recovering one product would mean out_k − out_{k−1} in soft logic: a 16-bit subtract plus a 16-bit register per channel, 32 times — more soft logic than the 8×8 multiply it removes (which synthesis already put on a DSP), and still one cycle late. Clearing the block each cycle is not an option either: a reset edge clears the operand registers too, so a reset-per-product scheme yields one product every two cycles at best.

Note on reset, for completeness: the retained value of mult across a mid-run rst is not observable (whenever mult_wr_en is 1, mult was written at that same edge), so the absence of a rst branch in spmv.v:3312-3323 is not by itself fatal; blockers 1 and 2 are.

The tile prize this forgoes is real and is why the region was examined: 32 blocks, two to a tile on one shared clk/rst, would be 16 DSP tiles against the baseline's 32 (−4.06e6 of 5.856e7 area units). It is not reachable correctly.

Candidates 2-4 — bvb.$mul$spmv.v:2490$57, spmv.$mul$spmv.v:163$11, spmv.$mul$spmv.v:172$13, left (one shared reason).

All three are a small counter times a constant power of two used as a barrel-shift amount: id >> (counter*8) (spmv.v:2490), data_out >> (counter_delay*16) (spmv.v:163), addr_out >> (counter_delay*8) (spmv.v:172). Synthesis turns each into a bit concatenation, so the baseline netlist holds no multiply cell and no soft adder for them — there is nothing for the block to absorb and no area to save. Strictly cost with no benefit under area × delay × wirelength.

The objective is area x delay x wirelength (delay register to register, 2026-10-20): VPR's total used logic block area (I/Os and empty grid tiles excluded) times the critical path times the total routed wirelength. Each term is the median over the loop's seeds; the product is the product of the medians. Beside every product stand the ratios against the baseline, A/A0 (area), D/D0 (critical path), W/W0 (wirelength) and their product, so the normalization can be read off. After each measured rewrite, the planner is given every measurement so far and asked for a revision. A revision is built and checked like the first rewrite, and the lowest product is kept, a later rewrite having to beat it by more than 8.73%. The loop stops when the planner declines to revise, when a revision does not lower the best product by more than 8.73%, when a revision fails its checks, or when 9 revisions have been made.
